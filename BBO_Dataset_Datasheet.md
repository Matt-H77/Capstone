# Datasheet for Dataset
## Bayesian Black-Box Optimisation (BBO) Capstone Dataset

## 1. Motivation

### Why was this dataset created?
This dataset was created to support optimisation of eight unknown black-box objective functions as part of a Bayesian Black-Box Optimisation (BBO) capstone project. The goal was to maximise each function while operating under a strict evaluation budget, requiring careful balance between exploration and exploitation.

Unlike a conventional machine learning dataset, this dataset records the sequential interaction between the optimisation algorithm and the unknown objective functions. Each new observation improves the surrogate model and informs future optimisation decisions.

### What task does it support?
The dataset supports:
- Bayesian optimisation
- Gaussian Process surrogate modelling
- Acquisition function optimisation
- Sequential decision making under uncertainty
- Comparison of optimisation strategies over multiple optimisation rounds

---

## 2. Composition

### Contents
The dataset consists of optimisation observations collected across ten optimisation rounds for eight benchmark functions.

Each observation contains:
- Input vector (continuous variables)
- Objective function output
- Function identifier
- Evaluation round

The benchmark functions vary from 2 to 8 input dimensions.

### Size and format
The dataset is stored as text files and NumPy arrays.

Each benchmark function contains:
- Initial design samples supplied at the start
- One additional observation collected each week
- Approximately 18–36 observations by the end of the project, depending on the function.

Each record is represented as:

```
(x1, x2, ..., xn, y)
```

where:
- `xi` are continuous decision variables
- `y` is the observed objective value

### Gaps
There are no missing values.

However, the dataset is intentionally sparse because only one expensive function evaluation could be submitted each week. This limited sampling budget is a defining characteristic of Bayesian optimisation.

---

## 3. Collection Process

### Data collection
The initial observations were supplied as part of the benchmark.

Each subsequent observation was generated by:

1. Training Gaussian Process surrogate models.
2. Generating candidate points using Latin Hypercube Sampling.
3. Filtering candidates using an SVM trained to identify high-yield regions.
4. Evaluating acquisition functions over the remaining candidates.
5. Selecting one candidate for submission.
6. Receiving the true objective value.
7. Appending the new observation to the dataset.

### Strategy
The optimisation strategy evolved throughout the project.

Early rounds prioritised exploration through higher uncertainty weighting.

Later rounds gradually shifted toward exploitation as additional information became available.

Additional techniques introduced included:
- Gaussian Process ensembles
- Expected Improvement (EI)
- Probability of Improvement (PI)
- Upper Confidence Bound (UCB)
- Thompson Sampling
- Dynamic exploration scheduling
- Adaptive acquisition parameters
- SVM high-yield filtering
- Candidate diversity analysis

### Time frame
The dataset was collected over ten optimisation rounds during the capstone project, with one new evaluation added each week.

---

## 4. Pre-processing and Intended Uses

### Pre-processing
Processing included:
- Appending weekly observations
- Scaling input variables where appropriate
- Gaussian Process hyperparameter optimisation
- Duplicate candidate removal
- Candidate filtering using calibrated SVM probabilities
- Ensemble prediction of means and uncertainties
- Calculation of EI, PI and UCB acquisition functions

Objective values were not transformed.

### Intended uses
This dataset is intended for:
- Bayesian optimisation research
- Sequential optimisation
- Surrogate modelling
- Active learning
- Acquisition function evaluation

### Inappropriate uses
The dataset should not be used for:
- General supervised learning benchmarks
- Classification tasks
- Large-scale deep learning
- Statistical inference beyond optimisation
- Real-world scientific modelling, as the benchmark functions are synthetic.

---

## 5. Distribution and Maintenance

### Availability
The dataset is maintained locally within the capstone project repository and updated after each optimisation round.

### Terms of use
The benchmark data were supplied for educational purposes. Generated optimisation data are intended solely for the capstone assessment.

### Maintenance
The dataset is maintained by the project author. Updates consist of appending new optimisation observations while preserving previous data. Version control is used to support reproducibility.

# BBO Optimisation Dashboard

A Streamlit dashboard for reviewing and presenting the results of the **Black-Box Bayesian Optimisation (BBO) Capstone Project**.

The dashboard loads weekly JSON optimisation reports and provides a human-readable view of optimisation progress, final submission candidates, Gaussian Process diagnostics, candidate comparisons, PCA analysis, and exploration–exploitation strategy.

---

## Overview

The app is designed to support analysis of eight black-box optimisation functions across multiple weekly iterations.

It reads JSON result files from:

```text
outputs/json/
```

using filenames such as:

```text
function_1_week_12.json
function_2_week_12.json
...
function_8_week_12.json
```

The interface allows the user to select a function and week from the sidebar and inspect the corresponding optimisation results.

---

## Main Features

### All-Function Overview

Displays a summary of every available optimisation run, including:

- Function number
- Week
- Objective direction
- Number of samples
- Number of dimensions
- Best observed raw output
- Optimisation progress
- Exploration and exploitation weights
- Source JSON file

### Final Submission View

The dashboard gives priority to a `final_submission_candidate` when one is present in the JSON.

If no specialist final submission exists, it automatically falls back to the normal `gp_hybrid_candidate`.

Final submission inputs are displayed to **six decimal places** for clear reporting and submission.

The dashboard also displays:

- Final selection method
- Predicted output
- Predicted standard deviation
- Distance from the best observed point
- Selection rationale, when available

### Optimisation History

Plots optimisation progress across weekly iterations.

The history view compares:

- Best observed raw output
- GP candidate prediction

The Y-axis is automatically scaled to make smaller optimisation improvements easier to see.

### Candidate Comparison

Compares candidate recommendations generated by:

- Gaussian Process / Hybrid approach
- Thompson Sampling
- Neural Network surrogate
- SVM candidate filtering
- Final specialist submission candidate, where available

Each candidate can be expanded to inspect its full input vector and associated diagnostics.

### Exploration vs Exploitation

Shows the current optimisation strategy, including:

- Progress through the available query budget
- Exploration weighting
- Exploitation weighting
- Acquisition-function `xi`
- Candidate pool size before and after filtering

### Gaussian Process Models

Displays the fitted Gaussian Process ensemble, including:

- Kernel type
- Fitted kernel parameters
- Log marginal likelihood

The optimisation framework uses a combination of:

- RBF
- Matérn
- Rational Quadratic

### PCA Diagnostics

Provides access to PCA and extended PCA diagnostics exported by the optimisation notebook.

These diagnostics are used to interpret:

- Search-space structure
- Explained variance
- High-performing regions
- Candidate proximity
- Cross-model agreement
- Relationships between principal components and objective performance

PCA is used for interpretation only and does not directly determine the optimisation candidate.

### Diagnostic Information

The diagnostics tab displays:

- Objective direction
- Output transformation
- Best raw output
- Best transformed output
- GP prediction in raw space
- GP prediction in optimisation space
- Final submission diagnostics
- Local GP diagnostics where available

---

## Objective Transformations

The optimiser internally reformulates all tasks into a maximisation framework.

The dashboard converts predictions back into a form suitable for interpretation where possible.

### Function 1

The optimisation target uses:

```text
log1p(abs(raw_y))
```

The dashboard reconstructs the predicted raw-output magnitude using:

```text
expm1(prediction)
```

Because the absolute value removes the sign, the original sign cannot be reconstructed.

### Functions 3 and 6

These functions are internally transformed using:

```text
transformed_y = -raw_y
```

The dashboard converts GP predictions back into the original minimisation space by negating the transformed prediction.

### Other Functions

Raw and optimisation-space outputs are directly comparable.

Create or activate a Python environment and install the required packages:

```bash
pip install streamlit pandas numpy altair
```

## Running the Dashboard

From the repository root, run:

```bash
streamlit run streamlit_app.py
```

Streamlit will start a local web server and open the dashboard in a browser.

---

## JSON Compatibility

The app supports the newer objective-aware JSON format while retaining compatibility with some earlier exports.

Important fields include:

```text
run
objective
best_observed
gp_hybrid_candidate
strategy
candidate_pool
gp_models
candidate_comparison
pca
extended_pca
```

Optional terminal-refinement fields include:

```text
final_submission_candidate
local_gp_diagnostics
function_7_terminal_diagnostics
function_8_terminal_diagnostics
```

If `final_submission_candidate` exists, it is treated as the actual candidate intended for submission.

---

## Final-Week Behaviour

In the final optimisation round, the project shifted from exploration toward terminal exploitation.

The dashboard therefore distinguishes between:

- the broad GP / hybrid recommendation, and
- the actual final submission candidate produced by any specialist terminal refinement.

This makes it possible to preserve the original optimisation diagnostics while clearly presenting the point ultimately selected for submission.

---

## Purpose

The dashboard is intended as a reporting and interpretation layer for the optimisation project rather than as the optimiser itself.

Its purpose is to make the optimisation process easier to inspect, explain, and present by combining:

- optimisation history
- surrogate-model predictions
- uncertainty
- candidate comparisons
- PCA diagnostics
- final submission decisions

into a single interactive interface.
